# Buzzle: передача работы по графике и полноценному 3D

Эта ветка сохраняет всю работу по новому стилю пчёл. Это отдельный прототип, не готовый выпуск. Не заменять основную графику автоматически.

## Задача от владельца

Нужны полноценные объёмные пчёлы, которые естественно поворачиваются в полёте в улье: вид спереди, сбоку и со спины. Новый объём должен сохранять одобренный стиль 2D-пчёл. Текущие 3D-попытки владельцу не нравятся: модели выглядят странно и недостаточно объёмно. Исправлять нужно подход к моделированию, а не только перекрашивать текущую геометрию.

## Что одобрено

- Стиль «медовый кристалл»: цельный корпус, мягко читаемые крупные грани, тёплый свет, тёмные выразительные глаза, розовые щёки, тонкие геометрические крылья. Не груша, не шар, не яйцо, не насекомое из отдельных головы/грудки/брюшка.
- 13 рисунков пчёл находятся в assets/art/bees-prototype/*-reference.png. Борис: использовать boris-reference-v2.png; первый boris-reference.png отклонён. Отличие Бориса — коренастый силуэт и тёмная пушистая грудка.
- Эталон Жужи: zhuzha-reference.png. Без короны: zhuzha-base.png.
- Анимация 2D: непрерывные взмахи двух отдельных крыльев, лёгкое покачивание, короткое моргание. Соня сохраняет закрытые глаза.
- Корона: crown-fitted-v3.png, посадка revision=20.
- Шарф: scarf-fitted-v4.png, увеличенная оборачивающая полоса с поднятым левым краем, revision=22.
- Сумка: satchel-left-accessory.png. Слева на экране, прижата к боку, передняя стенка смотрит влево, видимая боковая грань справа. Положение revision=28, ремень revision=29. Игровой ID backpack сохранён для совместимости.
- Берет: revision=30, естественная посадка, усики выходят через ткань.
- Бантик: на корпусе под лицом, не на усике; выровнен на 15° по часовой стрелке в revision=31.
- Венок: повышенная объёмность revision=31, выправленные поднятые края revision=32. Последняя версия одобрена.
- Очки реализованы; у Зоркой остаются её собственные очки.
- Уровень 5: золотистая окантовка и светлая искра на цветных крыльях. Уровень 10: корона; венок и берет заменяют её.
- Иконка приложения, Android adaptive foreground и favicon с Жужей подключены в app.json.

Внешний вид аксессуаров определяется не только PNG, но и креплениями/масками/преобразованиями в ReferenceBeeAccessories.tsx. Сохранить эти настройки.

## Что сделано технически

- src/ui/ReferenceBee.tsx: 13 рисунков, маски тела/крыльев/глаз, отдельные движения. Используется один ракурс.
- src/ui/ReferenceBeeAccessories.tsx: аксессуары, индивидуальные крепления, слои ремня и воротника, поправка формы венка и шарфа.
- src/ui/BeeSprite.tsx и BeeArtVariant.tsx: переключение старой графики, ранней 3D-попытки и рабочего референсного набора.
- src/screens/BeePreviewScreen.tsx: отдельный экран проверки; URL ?beePreview=1. Все пчёлы, наряды, уровни, улей, коллекция. Тестовые данные, не реальные сохранения.
- src/ui/anim.ts: три общих таймера крыльев 62/71/83 мс. Выбор по seed, не по виду. Разница скоростей заметна; владелец спрашивал, почему. Предложено унифицировать базовый ритм с разными фазами, отдельный более тяжёлый полёт Бориса. Это ещё не реализовано и не согласовано.

## 3D-попытки — НЕ эталон

1. Ранний Blender-прототип и 75 WebP-слоёв Жужи отклонены по стилю. Сцена outputs/zhuzha-prototype.blend; код prototype.py и render_lowpoly.py. Не переносить этот результат на всех пчёл.
2. outputs/zhuzha-turnaround: объёмный корпус с фронтальной проекцией рисунка, достроенные бок/спина, 32 ракурса, HTML с полётом над сотами. Отклонён.
3. outputs/zhuzha-turnaround-v2: исправленный свет, точные цвета лица и текстура/прозрачность крыльев. Тоже отклонён: не читается хороший объём и сходство с рисунком недостаточное. Последнее сообщение владельца: «все еще моделька очень странная; она выглядит вообще не обьемно; может нужно подключить какие то скиллы и библиотеки чтоб сделать модель лучше?»

Эти HTML показывают кадры реальной модели, но НЕ живой WebGL-рендер. Лицо нарисовано в текстуре, не вылеплено геометрией. Фаза крыльев привязана к кадру разворота, отдельного непрерывного цикла нет. Наряды/корона/моргание в этих образцах отсутствуют. Форма спины и боков не одобрена.

## Рекомендуемое направление следующей работы

Создать качественный объём по референсу. Сначала проверить Жужу без текстур: силуэт, объём лица, глаз, усиков и крыльев должны читаться самой геометрией. Затем материалы и спокойные грани. Подготовить согласованные виды спереди/сбоку/сзади. Возможный путь — image-to-3D через Meshy/Tripo, затем ручная доработка Blender. Эти сервисы не подключены; генерации через них не было. Аккаунт/API-доступ и совместимость нужно выяснить отдельно. Не обещать точное совпадение генерации заранее.

Для интерактивного просмотра рассмотреть Three.js/React Three Fiber; для текущего Expo/RN требуется отдельно проверить поддержку на Android. Не добавлять тяжёлый 3D-стек в основную игру до оценки модели. Также можно рендерить ракурсы модели в спрайты, если это лучше по нагрузке, но поворот и взмахи должны быть независимы.

- Предметы: 16 концептов на outputs/items-style-draft.png; отдельных новых игровых PNG нет. Снизить дробность граней до уровня пчёл.
- Сад: outputs/garden-style-draft.png — только мокап. Нужны ростки, стадии семи видов цветов, грядки. Флажки и гном пока без нового концепта.
- Перенос нового набора в основную игру, название сумки во всех языках, проверка масштаба/теней/нагрузки и реальное Android-устройство.

## Запуск и проверки

Рабочий 2D-просмотр:

```sh
npm ci
npm run web
```

В адрес Expo добавить ?beePreview=1. Параметр revision используется для отличия ссылок, не выбирает историческую версию.

Архивные 3D-просмотры:

```sh
python3 -m http.server 8100 --directory outputs
```

Открыть http://127.0.0.1:8100/zhuzha-turnaround-v2/ или /zhuzha-turnaround/. Рисунки и кадры лежат рядом с HTML, внешний сервис не нужен.

Повторная сборка последнего 3D-образца, если установлен Blender:

```sh
blender --background --python scripts/bees3d/turnaround_prototype.py
```

Проверки рабочего кода:

```sh
npm run typecheck
npm run test:ui -- --runInBand tests-rn/anim.test.tsx tests-rn/reference-accessories.test.tsx
```

Последние проверки 2D-прототипа: типы, 16 целевых тестов, web/Android export проходили. Это не проверка на физическом устройстве. Старые документы TESTING/STYLE относятся к ранним этапам, местами устарели.
