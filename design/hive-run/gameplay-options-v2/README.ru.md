# Королевская квота — варианты игрового экрана v2
Три нарисованных UX-направления, по два состояния на листе. Это ответ на недостаточную наглядность первого набора, не реализация механики и не новая утверждённая концепция.

A — Работы прямо в улье: три рабочих места в сцене, счётчики в зоне большого пальца, одна помощница освобождается из переработки и назначается на луг. Исходный план до показанных кадров 4/6/2, первый кадр уже после освобождения: 4/5/2 и 1 свободная, второй 5/5/2 и 0 свободных. Мёд при пяти переработчиках одинаков +20 на обоих кадрах. Фраза «меньше мёда» относится к исходному плану с шестью переработчиками, не к переходу между показанными кадрами. Блокировка запуска при свободных пчёлах — предложение для обсуждения, не утверждённое правило. Этот вариант потребует аккуратного масштабирования сцены, чтобы места и кнопки не стали мелкими.
B — План и результат: прогноз каждой группы прямо рядом с количеством. Второй кадр показывает причинный итог: 96+24=120 мёда, 12−1+2=13 пчёл; нектар +32 — сколько принесли, не конечный остаток после расхода на работу. Число 12 в плановой карточке — текущее количество, не точный прогноз с учётом случайной вылазки. Отсутствующая пчела показана светлым следом без мрачной серой фигурки. Самая ясная связь решения с результатом; рекомендован для первого теста понимания.
C — Подготовка в два шага: назначение 4/6/2, затем выбор луга для четырёх пчёл. Сезон запускается только последней кнопкой; переход между экранами не делает ход. В финальной реализации убрать ярко-красный цвет риска в пользу тёплого янтарного, сохранив текстовые уровни риска.

Все числовые прогнозы иллюстративны, формулы и ограничения из первого README не закрыты. Арт не доказывает удобство или баланс. После выбора нужен короткий прототип назначения/прогноза/результата, а не полная игровая система.

Инструмент: встроенный image_gen. Точные промпты, включая две адресные корректировки A/B, в prompts.json. PNG — исходные результаты без ретуши. WebP — просмотр, compare.png — механическая компоновка. Референсы: screens/v1.5/01-hive.png, исходная Жужа и первый главный экран режима. Изображения показывают новую идею сцен и рабочих мест; персонажи/инвентарь в них — концепт, а не новые утверждённые производственные ассеты. При реализации брать оригинальные BeeSprite и игровые изображения.

Статус всех трёх: черновики, сохранены по просьбе владельца. 28.10.2026: главный экран признан перегруженным; дальнейшая основа — существующий игровой улей, см. ../existing-hive-v3/. Старые макеты сохранены; код игры не менялся. Открытые вопросы по механике остаются в ../README.ru.md.
